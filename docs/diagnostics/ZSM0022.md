# ZSM0022 — When = true Is Ignored on a Concurrent Machine

**Severity:** Warning

A `[Transition(... When = true)]` was declared on a concurrent machine: a
`[StateMachine(Concurrent = true)]` class, or a `[StateMachinePart]` of a
`[StateMachineGroup]`, whose parts are always concurrent. Concurrent machines
do not support guards, so the generator emits no `Guard{Trigger}` stub and no
`when` clause for the transition. **The transition fires unconditionally.**

Concurrent machines commit a transition with a lock-free compare-and-swap. A
guard would have to be checked before that swap, and another thread can change
whatever the guard depends on between the check and the swap: a
time-of-check/time-of-use (TOCTOU) race. An unenforced guard is worse than no
guard, so the generator does not emit one. This diagnostic makes sure that the
`When = true` you wrote does not go unnoticed.

The diagnostic is reported at the `When = true` argument, once per guarded
transition.

## Example

```csharp
// ZSM0022: the guard is dropped, so Pay always moves Pending to Paid
[StateMachine(InitialState = nameof(OrderState.Pending), Concurrent = true)]
[Transition<OrderState, Trigger>(From = OrderState.Pending, On = Trigger.Pay, To = OrderState.Paid, When = true)]
[Terminal<OrderState>(State = OrderState.Paid)]
public partial class Order { }
```

## How to fix

Pick one of the alternatives from
[Concurrent Mode](../core-concepts/concurrent-mode.md#guards-and-concurrent-mode):

- **Encode the condition as a state.** Split the source state so that only the
  state in which the condition holds has the transition:

  ```csharp
  [StateMachine(InitialState = nameof(OrderState.PendingWithoutBalance), Concurrent = true)]
  [Transition<OrderState, Trigger>(From = OrderState.PendingWithoutBalance, On = Trigger.Fund, To = OrderState.PendingWithBalance)]
  [Transition<OrderState, Trigger>(From = OrderState.PendingWithBalance,    On = Trigger.Pay,  To = OrderState.Paid)]
  [Terminal<OrderState>(State = OrderState.Paid)]
  public partial class Order { }
  ```

- **Check the condition in the caller** and only call `TryFire` when it holds.
  Remove `When = true`, since it has no effect.
- **Drop concurrent mode.** Remove `Concurrent = true`, so that the guard is
  generated, and synchronise callers with an external lock.

If the transition is meant to fire unconditionally, remove `When = true`. It
has no effect on a concurrent machine, so removing it changes nothing at
runtime and makes the declaration say what the machine actually does.

The diagnostic is a warning, so existing builds keep compiling while you apply
one of these fixes.
