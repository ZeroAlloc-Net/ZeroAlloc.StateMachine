# ZSM0023 — Containing Type Is Not Partial

**Severity:** Warning

A `[StateMachine]` or `[StateMachineGroup]` type is nested in another type that is not declared
`partial`. The generated members are written into the nested type, inside `partial`
declarations of every containing type, and C# only lets a `partial` type be reopened. So the
generator reports ZSM0023 on the nested type and generates nothing for it. The message names
the outermost containing type that is not `partial`:

```
'MyApp.Orders.OrderMachine' is not generated because its containing type 'MyApp.Orders' is not partial
```

Without generated members, calls such as `TryFire` or `Current` on the machine fail to compile.
Earlier versions generated a nested machine into a new top-level type with the machine's
simple name instead, which left the nested machine just as empty.

## Example

```csharp
// ZSM0023: Orders is not partial
public class Orders
{
    [StateMachine(InitialState = nameof(OrderState.Pending))]
    [Transition<OrderState, OrderTrigger>(From = OrderState.Pending, On = OrderTrigger.Pay, To = OrderState.Paid)]
    public partial class OrderMachine { }
}
```

## How to fix

Declare every containing type `partial`:

```csharp
public partial class Orders
{
    [StateMachine(InitialState = nameof(OrderState.Pending))]
    [Transition<OrderState, OrderTrigger>(From = OrderState.Pending, On = OrderTrigger.Pay, To = OrderState.Paid)]
    public partial class OrderMachine { }
}
```

Or move the machine to the top level of a namespace.

The diagnostic is a warning, so a build that does not use the machine keeps compiling. Under
`TreatWarningsAsErrors` it fails the build.

See [Where the Host Can Be Declared](../source-generator.md#where-the-host-can-be-declared).
