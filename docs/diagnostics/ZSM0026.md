# ZSM0026 — Copies of a Timed Record Share Its Timers

**Severity:** Warning

A `[StateMachine]` or `[StateMachineGroup]` declared as a `record` has at least one timed
transition, `[Transition(... AfterMs = N)]`. Each timed transition keeps a
`System.Threading.Timer` in a field of the machine. A record's compiler-generated copy
constructor copies every field, so a copy made with `with` holds the same timers as the
original:

- the timers' callbacks still fire `TryFire` on the original, never on the copy;
- disposing the copy disposes the original's timers, so the original stops taking its timed
  transitions.

```
'Watchdog' is a record with timed transitions: a copy made with 'with' shares the original's timers, so disposing the copy stops the original's timers
```

The diagnostic is reported once per record, at its first `AfterMs` argument. The machine is still
generated. A record without timed transitions gets no diagnostic: its state is a plain value, and
a copy moves on its own.

A `record struct` cannot have timed transitions: `AfterMs` needs `Concurrent = true`, which a
struct cannot have, see [ZSM0004](ZSM0004.md) and [ZSM0012](ZSM0012.md).

## Example

```csharp
// ZSM0026
[StateMachine(InitialState = nameof(WdState.Idle), Concurrent = true)]
[Transition<WdState, WdTrigger>(From = WdState.Idle, On = WdTrigger.Tick, To = WdState.Fired, AfterMs = 5000)]
[Transition<WdState, WdTrigger>(From = WdState.Fired, On = WdTrigger.Reset, To = WdState.Idle)]
public partial record Watchdog;

var original = new Watchdog();
var copy = original with { };
copy.Dispose();   // original never fires Tick
```

## How to fix

- **Declare the machine as a class** when it does not need record semantics:

  ```csharp
  public partial class Watchdog { }
  ```

- **Do not copy the machine with `with`.** Create a new instance instead, which arms its own
  timers. Suppress the warning for that record once you have checked that no code copies it.

See [Timeout Transitions](../core-concepts/timeout-transitions.md).
