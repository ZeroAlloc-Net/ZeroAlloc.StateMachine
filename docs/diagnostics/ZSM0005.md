# ZSM0005 — Composite State on a Concurrent Machine

**Severity:** Error

`[CompositeState]` was declared on a `[StateMachine(Concurrent = true)]` class. Composite states require sequential dispatch through nested sub-FSMs; concurrent mode's single-CAS transition model cannot make that multi-step process atomic. The generator refuses to emit code that would be racy by construction.

## Example

```csharp
// ZSM0005: composite state on a concurrent machine
[StateMachine(InitialState = nameof(Parent.Idle), Concurrent = true)]
[Transition<Parent, Trig>(From = Parent.Idle, On = Trig.Start, To = Parent.Working)]
[CompositeState<Parent>(State = Parent.Working, SubMachine = typeof(WorkFsm))]
public partial class Outer { }
```

## How to fix

**Option 1 — drop concurrent mode.** Replace `Concurrent = true` with an external lock at the call site:

```csharp
[StateMachine(InitialState = nameof(Parent.Idle))]
[CompositeState<Parent>(State = Parent.Working, SubMachine = typeof(WorkFsm))]
public partial class Outer { }

// at the call site
lock (_outerLock) { _outer.TryFire(Trig.Start); }
```

**Option 2 — flatten the hierarchy.** Encode the sub-states directly in the parent's enum and declare flat transitions. Concurrent mode imposes no limit on the number of states.

See [Composite States — Concurrent mode](../core-concepts/composite-states.md#concurrent-mode) for the rationale.
