# ZSM0011 — Composite State Cannot Also Be Terminal

**Severity:** Error

The same state is declared both `[CompositeState]` and `[Terminal]`. These are contradictory: a composite state has internal dynamics (a sub-FSM that consumes triggers and may transition internally), while a terminal state explicitly has no outgoing dynamics.

## Example

```csharp
// ZSM0011: Parent.Working is both composite and terminal
[StateMachine(InitialState = nameof(Parent.Idle))]
[Transition<Parent, Trig>(From = Parent.Idle, On = Trig.Start, To = Parent.Working)]
[CompositeState<Parent>(State = Parent.Working, SubMachine = typeof(WorkFsm))]
[Terminal<Parent>(State = Parent.Working)]
public partial class Outer { }
```

## How to fix

Remove whichever attribute does not match the intent.

- If the state has a sub-FSM, it is composite — remove `[Terminal]`. The state can still lack outgoing parent-level transitions; the parent's own dispatch will silently fall through and the sub-FSM keeps running.
- If the state is a sink, remove `[CompositeState]` and the sub-machine class.
